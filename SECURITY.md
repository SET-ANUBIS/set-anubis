# Security policy

## Supported versions

Security fixes are handled on the latest released minor version. Before 2.0.0,
that means the `1.x` line.

| Version | Supported |
| --- | --- |
| 1.x | Yes |
| < 1.0 | No |

## Reporting a vulnerability

Please do not open a public issue for vulnerabilities. Use GitHub private
vulnerability reporting when available, or contact the maintainers at
[`anubis-active@cern.ch`](mailto:anubis-active@cern.ch).

Include:

- affected version or commit;
- minimal reproduction;
- impact assessment;
- whether optional integrations such as Pythia, HepMC3, MadGraph, Docker, MARTY
  or Dash are involved.

## Trust boundaries for scientific inputs

SET-ANUBIS processes scientific files that are more powerful than ordinary data
files. Treat the following inputs as trusted code or trusted serialized state.

### Pickle files

Python pickle formats, including `.pkl`, `.pickle`, `.pkl.gz` and
pickle-containing database bundles, can execute arbitrary Python code while they
are loaded. SET-ANUBIS uses pickle for lightweight example bundles and for
selection/database caches that preserve object-valued DataFrame columns.

Only load pickle files that:

- were generated by your own trusted SET-ANUBIS workflow;
- are shipped in an official SET-ANUBIS source release; or
- come from a collaborator or archive whose integrity and provenance you have
  independently verified.

Do not load an untrusted pickle merely to inspect it. File extensions, gzip
compression and SHA-256 integrity checks do not make a malicious pickle safe.
When exchanging data across trust boundaries, prefer CSV, JSON, YAML or Parquet
where the relevant schema supports the required data types.

The CPC examples in `reproducibility/` use the bundled CSV inputs and do not load
pickle files.

### UFO models

UFO models are Python source trees. Parsing or importing a UFO may execute its
Python modules, including `parameters.py`, `particles.py`, function libraries
and parameter-card writers. Only use UFO directories from trusted sources and
review changes before replacing a model in an established analysis.

### Generated MARTY, MadGraph and job inputs

Generated C++ sources, MARTY parameter files, MadGraph command cards, job
scripts and container images affect programs executed outside the Python
interpreter. Review externally supplied inputs before compilation or execution.
`MartyCompiler` invokes executables with explicit argument lists and does not use
a command shell, but trusted-source requirements still apply to generated source
code and binaries.

### Paths and output directories

Use dedicated, non-privileged output directories. Avoid running generators or
containers as root, and do not mount sensitive host directories into MadGraph or
other development containers. The development MadGraph helper reads its host
input path from `SETANUBIS_MADGRAPH_INPUT_DIR` and defaults to a repository-local
`input_files` directory.

## Dependencies and external software

SET-ANUBIS wraps external scientific software. Vulnerabilities in Pythia8,
HepMC3, MadGraph, MARTY, Docker, FastJet or system packages should also be
reported to the corresponding upstream projects. Keep Python and external
dependencies updated, review dependency-audit results, and pin complete
production environments used for published results.
